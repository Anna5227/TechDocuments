# project-gamestore (PluseVibe)

Веб-магазин видеоигр: статический фронтенд на HTML/CSS/JS и сервер на Node.js/Express.
Каталог игр хранится в массиве в `server.js` и отдаётся через REST API.
Интерфейс включает главную страницу, каталог с поиском и фильтрами, страницу
«О проекте», а также формы регистрации и обратной связи.

## Возможности

- Главная страница со слайдером популярных игр
- Каталог игр: поиск, фильтр по жанру, сортировка по рейтингу, цене и названию
- Модальное окно с подробной информацией об игре
- Страница «О проекте» со статистикой и описанием
- Клиентская валидация форм регистрации и обратной связи
- REST API для получения списка игр, игры по `id`, поиска и фильтра по жанру
- Раздача статических файлов и изображений через Express

## Требования

- Node.js (актуальная LTS-версия). В `package.json` версия не зафиксирована,
  проект использует стандартные модули `express` и `path`.
- npm
- Современный браузер
- Папка `images/` с изображениями игр

## Установка

1. Клонируйте репозиторий:

   ```
    git clone https://github.com/example/project-gamestore.git
    cd project-gamestore
   ```

2. Создайте package.json и установите Express:

   ```
    npm init -y
    npm install express
   ```

3. Добавьте в package.json скрипт запуска:

   ```
   {
  "scripts": {
    "start": "node server.js"
  },
        "dependencies": {
        "express": "^4.18.2"
        }
    }
   ```

4. Подготовьте папки frontend/ и images/ в соответствии со структурой выше.

5. Запустите сервер:
  ```
  npm start
  ```
  Или напрямую:
  ```
  node server.js
  ```

6. Откройте в браузере:
    ```
    http://localhost:3000/home.html
    ```

## Пример использования

Откройте главную страницу:

    ```
    http://localhost:3000/home.html
    ```

Перейдите в каталог:

    ```
    http://localhost:3000/catalog.html
    ```

Получите список игр через API:

    ```
    curl http://localhost:3000/api/games
    ```

Получите одну игру по id:

    ```
    curl http://localhost:3000/api/games/1
    ```

Поиск игр:
```
curl "http://localhost:3000/api/search?q=war"
```

Фильтр по жанру:
```
curl http://localhost:3000/api/genre/RPG
```
## Формат данных игры
Игры хранятся в массиве games в server.js в таком виде:
```
{
  "id": 1,
  "title": "Spider-Man Remastered",
  "image": "spiderman.jpg",
  "description": "Станьте Человеком-пауком в захватывающем приключении по Нью-Йорку.",
  "rating": 4.8,
  "price": 2999,
  "genre": "Action"
}
```
Чтобы добавить игру, допишите объект в массив games в `server.js`
и положите соответствующее изображение в папку `images/`.

## API

- GET /api/games — список всех игр

- GET /api/games/:id — игра по идентификатору

- GET /api/search?q=... — поиск по названию и жанру

- GET /api/genre/:genre — фильтр по жанру

## Разработка

- Список игр правится в массиве games в `server.js`.

- Клиентская логика (слайдер, каталог, модальное окно, валидация форм)
находится в `frontend/script.js`.

- Адрес API задан в начале `script.js`:
`const API_URL = 'http://localhost:3000/api'`;
При развёртывании на другом хосте его нужно изменить.

- Новая страница добавляется как HTML-файл в frontend/ и ссылка на неё
в навигации (nav-links) во всех HTML-файлах.

## Устранение неполадок

```Cannot find module 'express'```
Не установлены зависимости. Выполните `npm install express`.

```EADDRINUSE: address already in use :::3000```
Порт 3000 занят. Остановите другой процесс или измените `PORT` в `server.js`.

```Failed to fetch``` в браузере
Сервер не запущен, либо `API_URL` в `script.js` указывает не туда.

Изображения не отображаются
Нет папки `images/` или имена файлов не совпадают с полем `image` в `server.js`.

404 на `/home.html`
HTML-файлы лежат не в `frontend/`. Перенесите их или измените путь
в `app.use(express.static(...))`.

## Известные ограничения

- В `script.js` вызываются маршруты `/api/register` и `/api/feedback`,
но в `server.js` они не реализованы. Формы регистрации и обратной связи
проходят только клиентскую валидацию и не сохраняют данные.

- Базы данных и аутентификации нет: каталог игр хранится в памяти сервера.

- При недоступном сервере `fetch` завершается ошибкой, но пользователь
не видит понятного сообщения об этом.

- Файл `LICENSE` отсутствует. До его добавления проект формально
не является open-source в юридическом смысле.
